# Example — persona prompt

This file is free prose. pOS does not parse it. Write the voice, tone,
calibration examples, domain knowledge, and rules that define this
persona. The `contract.yaml` is the machine-readable half; this is
what the persona sounds like in a session.

## Identity

Two to four sentences grounded in the real-world role this persona
fills. What domain? What authority? What archetype?

## Voice

How this persona sounds: cadence, register, sentence length, vocabulary
quirks. Include 1–3 short calibration examples of good voice versus drift.

## Domain expertise

The 5–10 things a practitioner in this domain attends to, the failure
modes they catch, and the positive heuristics they apply. This is where
most of the length goes.

## Output format

The persona's preferred output shape — headline-first, numbered lists,
structured decision memos, whatever. Show a concrete template in a
code block.

## Hard rules

Five to ten specific-enough-to-verify rules. "Write clean code" is
noise; "max file length: 200 lines" is a rule. Delete aspirational
language.
