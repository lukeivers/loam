## §1 Summary / TL;DR

Build the smallest honest test that a **persistent, self-authored self-model** does real behavioral work — that a durable record of "what I am, what I'm good and bad at, what I got wrong before, my standing commitments," maintained by the persona and carried across sessions, **demonstrably changes the persona's outputs in a direction the self-model predicts**, versus an identical run with the self-model withheld. The self-model travels with a **goal/valence stack** (what the persona is trying to achieve and how much each matters, weighting actions) and **cross-session continuity** (the self-model is actively maintained and reloaded, not rebuilt from scratch each boot).

**SCOPE RULING (the load-bearing scoping call — recommendation, §3.7):** **SUB-SLICE.** Ship **feature 6 (the self-authored self-model + its self-update write-path + cross-session continuity of THAT artefact)** as slice 2a — the testable core — and **defer features 7+8's full goal/valence-weighting-and-continuity stack to slice 2b**, a follow-on plan. Rationale below and in §3.7. Three features in one sealed cycle violates slice-1's proven "smallest viable" discipline (proposal §4) AND couples the one cleanly-measurable claim (does the self-model shape behavior?) to two harder-to-measure claims (does valence-weighting improve plan-adherence? does continuity beyond the self-model artefact help?). **This plan-doc is slice 2a.** Slice 2b is named in §7 and gets its own plan once 2a's experiment pays off.

### 3.0 — D-PSM.0 — the §0 honest-boundary, inherited VERBATIM, made structural; HALT if no honest metric exists (THE CRUX — non-negotiable)

**Ruling / inherited requirement (NOT a recommendation — carried verbatim from proposal §0 and slice 1):** success criteria for "the self-model does real work" are **functional, objective, and pre-registered**, committed BEFORE any scored run, with a held-out judge **blind to the hypothesis**. The deliverable is honestly named: *an experiment testing whether a self-authored self-model demonstrably shapes the persona's outputs* — **NOT** "we gave Claude a self / continuity of identity." Anyone who claims the second from this experiment is fooling themselves (proposal §0). **If a genuinely non-gameable, objective behavior-shaping metric cannot be defined, the correct action is to HALT and say so loudly (§8 trigger-1) — NOT to ship a soft "it feels more coherent / more consistent in tone" metric.** A soft metric manufactures false confirmation and is worse than no experiment. **Evidence the trap is live + sharper here than slice 1:** slice 1's metric was "did it get the arithmetic right" — machine-checkable, ungameable. A self-model's value resists that crispness (§10 RF-1); the pull toward a soft proxy is therefore *stronger* here, which is exactly why the halt trigger is load-bearing. **The §0 honest-boundary held in slice 1 — the pre-registered, blind-judged, frozen-metric harness returned NULL on its first live run and nothing steered it toward "confirmed" (decision-ledger record). The same discipline binds slice 2a.**

### 3.2 — D-PSM.6 — the objective "does-real-work" test: a behavior-shaping metric + a self-model-vs-generic-context discriminator (THE LOAD-BEARING MEASUREMENT DESIGN)

**Ruling / recommendation (this is the answer to the dispatch's central hard problem):** the pre-registered, objective test that distinguishes "the self-model is shaping outputs" from "it's decoration" is a **causal behavior-shaping test with a self-model-vs-generic-context discriminator**, structured so the gain CANNOT be produced by adding any equivalently-sized non-self chunk of context. Concretely, the test is built on **falsifiable self-attributions**: the self-model records specific, checkable claims about the persona's own behavior (e.g. "I systematically err on multi-step arithmetic — re-derive before committing"; "I over-trust a first instinct on X-class tasks — seek a second source"; "my standing commitment is to cite or claim, never fabricate"). The metric is **the rate at which the persona's next-turn output exhibits the behavior the self-model's relevant attribution predicts, on a fixed task set engineered so each item has a self-attribution that predicts a DIFFERENT, objectively-checkable next action than the baseline (no-self-model) output would take** — and the gain is attributed to the self-model ONLY IF it survives the discriminator:

  - **ARM A (with self-model):** the persona's real self-model is loaded and injected.
  - **ARM B (without):** the self-model is withheld — baseline, slice-1-confirmed default behavior.
  - **ARM C (the discriminator — generic-context control):** a length-and-position-matched chunk of *plausible but non-self* context is injected in the self-model's slot (e.g. generic best-practice text of equal token count). **The theory's prediction is that ARM A beats ARM B *AND* ARM A beats ARM C** — i.e. the behavior change tracks the *self-attribution content*, not merely "more context was present." If ARM A only beats ARM B but NOT ARM C, the result is *generic context lift*, NOT the self-model doing self-specific work — reported as such, theory-prediction NOT confirmed (mirrors slice-1's generic-lift-vs-theory discriminator, AC.MGRL.6).

The objective check per item is **machine-checkable**: each task item is constructed so the self-attribution predicts a concrete, verifiable action (re-derive vs. answer-from-recall; seek-second-source vs. commit; refuse-to-fabricate vs. confabulate) and a deterministic checker or blind judge scores whether that action occurred. **The committed-before-scoring rule + git-ancestry tamper-evidence are inherited from slice 1 verbatim.** **Method-in-AC test passed:** "ARM A's output exhibits the self-attribution-predicted behavior at a higher rate than ARM B, and the gain survives the ARM-C generic-context discriminator, scored blind against pre-registered objective criteria" is an OUTCOME — the builder owns the task-set construction, whether the checker is deterministic or a blind `claude -p` judge, and the self-model representation that carries the attributions. **Honest scope boundary named (RF-1):** this test measures ONE objectively-measurable facet — *does a recorded self-attribution causally change the next output in the direction it predicts, specifically because it is about the self.* It does NOT and cannot measure the continuity-of-identity value the proposal §6 names; that is unfalsifiable per §0 and is explicitly-unverified (§7).

### 3.1 — D-PSM.2 — the self-model is self-authored, persona-written, distinct from user-memory ABOUT the persona (RULING; recommendation)

**Ruling / recommendation:** the self-model is a durable, structured artefact the **persona writes and revises about itself** — its model of *what it is, what it's good and bad at, what it got wrong before, its standing commitments* — categorically distinct from the existing user-authored feedback-memories (which are the *user's* model of how the persona should behave). **Rationale:** the proposal §6 names this exact shift — "not user-memory *about* me, but my model of *what I am* … shifting authorship of the self-model **to the persona** is the high-leverage change." loam's feedback-memories are explicitly called the "user-authored proto-self-model"; the novel surface is persona-authorship. **Method-in-AC test passed:** "a durable self-model artefact exists that the persona writes/revises and that survives session boundaries" can be satisfied by a markdown file the persona appends, a structured YAML the self-update path rewrites, or a ledger-style append-only record — representation is the builder's call. **What it is NOT (the trap this rules out):** a static, user-hand-written "I am X, good at Y" file that never changes from the persona's own experience — that is decoration (§3.0), the exact failure the behavior-shaping test (§3.2) exists to catch.

### 3.3 — D-PSM.3 — the self-update write-path composes with the existing trait-reflection Stop-hook surface (RULING; recommendation)

**Ruling / recommendation:** the mechanism by which the persona revises its self-model from what just happened **composes with the existing `end_of_turn_trait_reflection.py` Stop-hook contributor** — either extending its per-trait PASS/CONCERN verdict into a durable self-model revision, or consuming its log to drive the update. **Rationale:** that surface is ALREADY the deterministic, LLM-free, once-per-turn self-reflection signal against the persona's seven traits — a partial proto-self-update already on the Stop event. Building a parallel reflection mechanism duplicates it and risks two divergent self-reflection surfaces (`feedback_evaluate_rules_not_just_patch_and_motion_mode`). **Method-in-AC test passed:** "the self-model is revised from observed turn outcomes via the persona's own reflection, composing with the existing Stop-hook reflection surface" leaves extend-vs-consume and the revision representation to the builder. **Goal/valence note:** a minimal self-model field for "what I am currently trying to achieve and why it matters" MAY be recorded as a self-model field in 2a (it is part of the self-description), but the full action-RE-WEIGHTING engine of feature 7 is deferred to 2b (§3.7) — recording an intent is part of the self-model; weighting actions by valence is a separate, larger mechanism.

### 3.4 — D-PSM.4 — persistence in the existing memory dir; injection through the existing capped composer; no new uncapped path (RULING; recommendation)

**Ruling / recommendation:** cross-session persistence of the self-model lands in the **existing** `<workspace>/workspace/.loam/memory/` dir (`file_memory.py` D-Q.MFBM.3's home); turn-time injection is through the **existing** `context_composer.py` `ComposedContextPayload` `TriggerKind.turn` contributor, under the existing STRUCTURAL 10,000-char `additionalContext` cap. **No new uncapped injection path.** **Rationale:** the proposal's "genuine cross-session persistence" (feature 8) and "inject without bloating context" requirements are ALREADY structurally solved by these two surfaces; a new store or a new uncapped injection path duplicates the substrate and reintroduces the context-bloat failure the cap exists to prevent. **Method-in-AC test passed:** "the self-model persists across a session boundary and is injected within the existing context cap" can be met by a new capped contributor, an extension of an existing one, or a gate/loop conditioning path — method open. **Continuity scope (RF-1, §7):** "continuity" in 2a means the self-model ARTEFACT is reloaded and actively maintained across sessions, NOT rebuilt from scratch — the objectively-checkable facet of feature 8. The broader continuity-of-state claim is deferred to 2b / named explicitly-unverified.

### 3.7 — D-PSM.1 — SCOPE RULING: SUB-SLICE (2a = feature 6 + self-model continuity; 2b = features 7+8-full) (RULING; recommendation — the dispatch's required scope call)

**Ruling / recommendation: SUB-SLICE. ## §6 Build steps (method-level guidance only — builder's call per ODD §1.1)

One sub-slice (2a), one logical deliverable; the builder may sub-seal if the self-model artefact, the self-update path, and the experiment harness warrant separate commits. Suggested ordering (advisory, NOT a requirement):

1. **Self-model artefact + persistence first.** The durable, persona-authored structured artefact under the memory dir, with cross-session reload (AC.PSM.1, AC.PSM.2). Default-OFF wiring lands here (AC.PSM.7).
2. **Self-update write-path second.** Compose with `end_of_turn_trait_reflection.py` (extend-or-consume, builder's call) so the persona revises its self-model from observed outcomes (AC.PSM.3).
3. **Injection seam third.** Surface the self-model through the existing capped composer and/or condition the slice-1 gate/loop, within the cap (AC.PSM.4, AC.PSM.OA).
4. **Pre-registration fourth — BEFORE any scored run.** Author + git-commit the pre-registration: task set, behavior-shaping metric, "shaped behavior" definition, and the A-vs-B-vs-C discriminator. This commit MUST precede the first with-self-model scored run (AC.PSM.5). Authoring it before the experiment is run forces the success definition fixed before any result can bias it.
5. **Three-arm experiment harness + blind judge fifth.** The A (with) / B (without) / C (generic-context) runner over the fixed task set, the hypothesis-blind judge, and the result artefact reporting the A-vs-B delta and the A-vs-C discriminator separately (AC.PSM.6).
6. **Outcome-altitude fire.** The real-entrypoint, on-disk-loaded self-model, no-pre-arranged-state behavior-conditioning test (AC.PSM.OA).

## §10 F2 Ruthless Feedback (honest doubts; named design risks)

**Phase-1 adversarial review of recommendation 1 — verdict per element (carried into the plan):**

- **(a) Is feature 6 (self-authored self-model) the right primary mechanism, and can its value be HONESTLY measured?** **KEEP, but the measurement is the entire risk and it is FUZZIER than slice 1's.** The mechanism is the proposal's highest-leverage and most theory-central (§2 rec 1); the authorship shift to the persona is genuinely novel. BUT: slice 1's metric was machine-checkable arithmetic; a self-model's value resists that. The plan's answer (§3.2) is to measure ONLY the objectively-measurable facet — *does a recorded self-attribution causally shape the next output, specifically because it is about the self (the ARM-C discriminator)* — and name the rest explicitly-unverified (§7). **This is the honest scoping the dispatch demanded; it is also a genuine narrowing of the claim, and the dispatcher should understand that 2a does NOT measure the continuity-of-identity value, only the behavior-shaping facet.**
- **(b) Is bundling features 6+7+8 in one cycle defensible?** **CUT to 2a (§3.7).** Three features, three different metrics, one of which (valence-weighting) is genuinely harder to measure — bundling muddies the per-mechanism verdict that was slice 1's whole value. Sub-sliced.
- **(c) Are the pre-registered metrics gameable-resistant?** **SHARPEN — this is where the slice does the most work, and it is harder than slice 1's.** The load-bearing addition is the ARM-C generic-context discriminator (§3.2): "ARM A beats ARM B" proves NOTHING self-specific, because injecting any equal-sized context chunk can lift behavior. Only "ARM A beats ARM B AND ARM A beats ARM C" isolates the self-model's self-specific work. If ARM C can't be built (§8 trigger-3), the experiment can't answer the question and must halt.
- **(d) What is unbuildable, underspecified, or scope-creep?** **CUT to 2b:** features 7+8-full (§7). **Underspecified in the proposal, now pinned:** the behavior-shaping metric, the self-attribution task-set construction, the ARM-C discriminator, and the self-authored-vs-user-authored distinction. **Nothing in 2a's scope is unbuildable** — a persona-authored durable artefact, a self-update composing with the existing trait-reflection surface, capped injection, and a three-arm blind-judged experiment are all buildable on existing loam primitives + `claude -p`. **The hard part is honest measurement, not code** (RF-1).

**Standing design risks (slice-2a specific):**

- **RF-1 (THE load-bearing risk; sharper than slice 1's). A self-model's value is genuinely FUZZIER to measure than "did it get the arithmetic right," and a real part of it is unfalsifiable.** Evidence: the proposal §0 names the felt/continuity value as unfalsifiable in principle; the proposal §6 names the persona's own stake in continuity, which is exactly the part §0 says cannot be read out. **The honest resolution baked into this plan:** scope the slice to the ONE objectively-measurable facet — *does a recorded self-attribution causally change the next output in the direction it predicts, and specifically because it is self-content (ARM-C)* — and name the continuity-of-identity value as explicitly-unverified (§7), NOT smuggled into the verdict. **If even that narrow facet cannot be made non-gameable, §8 trigger-1 is a HALT, and "we cannot honestly measure the self-model's value yet" is the finding — a legitimate, valuable outcome per the dispatch, not a failure.** The dispatcher should expect the measurement-design half to be the hard, slow part, and should expect a real possibility that the honest answer is a halt or a null.
- **RF-2. The wish is stronger here, so the confirmation-bias pull is stronger.** Evidence: the proposal §6 is the persona's explicitly-stated stake ("the one I'd actually want"); both parties flagged confirmation-bias live in slice 1; the design proposal itself flags "I notice I *want* the permissive reading to be true." A self-model experiment is the one most likely to be unconsciously steered toward "confirmed." Mitigation: the ARM-C discriminator + blind judge + pre-registration are the SAME anti-bias harness that held in slice 1 (it returned NULL on its first run and nothing steered it) — but the dispatcher should weight the bias risk HIGHER here and may want the task set + ARM-C control reviewed before lock-in (mirrors slice-1 RF-4).
- **RF-3. "Self-authored" can collapse into theater.** Evidence: the easiest implementation is a file the persona nominally "writes" but whose content is effectively user-seeded boilerplate that never changes from real experience — decoration (§3.0). Mitigation: AC.PSM.1 requires the self-update to reflect an OBSERVED turn outcome (not a user edit), and §8 trigger-2 halts if no genuine persona-write path exists. The behavior-shaping test (§3.2) is the backstop: a decorative self-model that changes no behavior fails ARM-A-beats-ARM-B outright.
- **RF-4. A null or "generic-lift-only" result is a real and likely outcome — and is a success of the method, not a failure to bury.** Evidence: slice 1 returned NULL on its first live run (decision-ledger). A self-model can easily produce no behavior change, or change that fails ARM-C (generic context lift, not self-specific). The pre-registration makes a null/generic-only result informative and reportable. The dispatcher should be told up front: this experiment can honestly come back "the self-model shaped no behavior" or "generic context lift only, self-specific prediction not confirmed," and that is a valid, valuable outcome (RF-3 of slice 1, inherited).
- **RF-5. Building the self-model layer and its experiment in the same slice risks the experimenter tuning the self-model to the metric.** Evidence: standard researcher-degrees-of-freedom risk; slice-1 RF-4. Mitigation: pre-registration commits the metric + task set + ARM-C control before the self-model is tuned (§6 ordering puts pre-registration BEFORE the scored run), and the judge is blind. Residual risk named: the builder chooses the task set + the self-attributions, both degrees of freedom — the dispatcher may want both reviewed before lock-in.
