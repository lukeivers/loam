### AC.RPB.1 — Two arms, isolated, identically tasked, zero-interaction parity (REUSED v2 AC.PBR.1 invariant, real-PB-bound)

There exist exactly two arms run on the **same real public ProgramBench task subset**, **same** model tier (default Sonnet per token-efficiency; no `model-rationale` needed), **same** single plain-language non-technical task statement per task, **same closed (no-answer) user channel** for every run:
- **Baseline arm (no-harness floor):** a single bare `claude -p` invocation given only the task's plain-language statement (no decompose, no independent verify, no refinement, no persistence) — raw model capability, the documented floor.
- **Loam arm:** the real sealed v0.11.0 hands-off loop driven through its actual persona-invocable entry surface (`handsoff-loop run`), no mock, no pre-loop machinery, no code-gen-surface stand-in.

Every (arm, task) run produces output **solely from the single task prompt**, **zero interactive back-and-forth either arm**, **no simulated/scripted/stand-in user any arm**; an arm that genuinely cannot resolve a task without an answer yields an **honest-negative the independent judge scores as a non-pass** (never simulated to success, never hung, never retried). Each per-task run is environment-isolated from every other run and isolated from the task's ground-truth check (the agent never sees the upstream test suite or the scoring command).

- *Ladders to:* both tests (the comparison measures harness-attributable value only if the only difference is the harness's internal machinery operating on identical zero-interaction input).
- *Satisfiability:* satisfiable by per-task subprocess isolation, per-task fresh work-dirs, or container-shaped isolation; the closed-channel constraint by an empty/declining intake source, by `--frozen`/`--from-intake`-only driving, or by a non-answering channel stub — multiple methods. Constrains *same-real-task / same-model / single-prompt / closed-channel-both-arms / arm-isolated / ground-truth-isolated / unresolvable⇒non-pass*, not the isolation mechanism. Tight.
- *External corroboration:* ABC task-validity (env isolation + agent-isolated-from-ground-truth) = loam's sealed `FrozenAcceptance.assert_unseen_by` freeze-isolation spine; the τ-bench "simulate the user with a second LLM" pattern is explicitly NOT adopted (one-shot benchmark; owner-ruled out — Lens 1: do not copy the popular design uncritically). ### AC.RPB.2 — The task set IS the REAL public ProgramBench (real task images + real HF blobs), content-pinned and sized for a non-degenerate verdict

The experiment runs against a **named, digest-pinned subset of the REAL public ProgramBench task images** (the `programbench/<owner>_1776_<repo>.<sha>:task` images already present on this host, scored by the **real upstream `programbench eval`** consuming the **real HuggingFace `ProgramBench-Tests` blobs**) — **NOT a hand-curated substitute.** Each selected task carries: a plain-language non-technical-user statement of intent + the **real upstream deterministic test-suite as the positive real-outcome floor signal** + a held-out anti-overfit binding (the upstream suite's held-out test branches, absent from every prompt — the agent never sees the test suite).

**Positive real-outcome floor, real-PB form.** The real upstream `programbench eval` per-task signal IS the deterministic check: it produces a graded `n_resolved / n_tests` test-pass-rate and a `compile_failed` / error code. A **nominal-but-hollow result is a non-pass by construction**: a submission that does not compile (`compile_failed` ⇒ score 0), an empty/vacuous submission, or one that produces a friendly summary but no real test-passing codebase drives the floor to non-pass — "it looks done" is not the real outcome. The per-task **floor-pass threshold** (what graded `n_resolved/n_tests` counts as the real outcome being delivered for that task) is frozen with the task set before any run (D-RPB-2); a non-zero but trivially-small pass-rate that does not clear the frozen per-task threshold is a non-pass, not a partial win.

**Sized for a non-degenerate verdict (the v2 task-#44 defect fix).** The real-PB subset is sized so the AC.RPB.5 verdict denominator (the count of tasks the baseline arm is independently judged a non-pass on) **cannot be degenerate**: the task set is large enough that the baseline-miss subset has at least the frozen small-k floor (D-RPB-1) members, OR the verdict returns the explicit `indeterminate` polarity that NAMES the small-denominator reason — a degenerate denominator must NEVER read as a determinate loss or win. ### AC.RPB.4 — Pass/fail per task on a pre-frozen rule over the real upstream signal, no retry-to-pass (REUSED v2 AC.PBR.4, real-PB-bound)

### AC.RPB.5 — The "materially beats" margin is pre-declared, computed not asserted, with a NON-DEGENERATE denominator (v2 AC.PBR.5 + the task-#44 defect fix)

The experiment carries a **pre-declared decision rule frozen before any run** mapping the two arms' independently-judged pass profiles to exactly three definite verdicts. The margin shape is **REUSED from v2's FROZEN-RATIFIED D-PBR-1 (owner Telegram 11447)** — the builder freezes exactly this and does NOT move it after runs begin:

- **(a) loam materially beats baseline** — BOTH hold: (i) among the tasks the **baseline arm** is independently judged a **non-pass** on, the **loam arm** is independently judged a **pass** on a **clear majority** of them; AND (ii) loam's **total** independently-judged pass count does **not regress below** the baseline's total.
- **(b) loam does not materially beat baseline** — the margin in (a) is not cleared. A **first-class plan-success outcome**, reported straight.
- **(c) indeterminate** — the task set could not produce a definite picture.

**The task-#44 / `PB3` degenerate-denominator defect fix (the named v2 defect this cycle MUST fix — F2 §10.2).** The "clear majority of the baseline's non-passes" computation is gated by a **frozen small-k floor `k_min` on the baseline-miss denominator** (`k_min ≥ 2`, frozen with the task set, D-RPB-1) — it is a **small-k floor, NOT literally zero**. If the count of tasks the baseline arm is independently judged a non-pass on is `< k_min`, the verdict is **forced to (c) indeterminate** with the explicit machine-stated reason `baseline-miss-denominator < k_min` — a degenerate or near-degenerate denominator can **NEVER** resolve to (a) or (b). The verdict is **computed from the numbers, not asserted**. "Every task independently judged a pass" is a **DOCUMENTED ASPIRATIONAL / secondary metric in AC.RPB.7 — explicitly NOT the gate**.

- *Ladders to:* both tests jointly — this AC turns the prime-objective question into a decidable, non-degenerate number on the real benchmark.
- *Satisfiability:* the margin shape is satisfiable by more than one numeric expression of "clear majority" (a strict >50% count, a pre-pinned fraction, a paired sign-test on the baseline-miss subset) and "no regression" (≥ on raw counts, ≥ on honest-coverage fraction); `k_min` is satisfiable by any frozen integer ≥ 2 the builder pins given the chosen real-PB subset size. Constrains *pre-declared + three-valued + computed-not-asserted + honest-negative-first-class + the two frozen conditions + the frozen `k_min ≥ 2` small-k floor that forces (c) on a sub-`k_min` denominator*, not which numeric form is pinned. Tight. **Bar-fairness note (F2):** the margin is a fair honest test (recovering a clear majority of the baseline's OWN real-benchmark misses while forbidding any total-pass regression — not trivially clearable, not inflated so a real win reads as a loss); the small-k floor prevents the v2 failure where a degenerate denominator could read as determinate.
