## §1 Summary / TL;DR

**What ships.** A `SubagentStop` hook that, when a dispatched subagent FINISHES, evaluates the subagent's result **out-of-band** — a fresh evaluation seeded with ONLY the microkernel (`kernel/loam-microkernel.md`) + the subagent's stated objective + its result, and explicitly NOT the polluted parent conversation — judging frame-consistency: "is this output consistent with loam's core? was the objective the one actually requested?" Off-frame → the hook SURFACES the flag to the dispatcher (non-blocking for v1); on-frame → the hook is a silent no-op. The judge runs as an **isolated `claude -p`** (subscription-only; no Anthropic API key) via the sealed `spawn_isolated_claude` entry-point, so it cannot steal the Telegram bot slot. It fires only on **structural-cue triggers** (consequential subagents — those that wrote deliverables / mutated state), keeping it cheap + bounded. Every path is **fail-soft**: a judge error never aborts, never blocks. This is component **J** from the integrated design instantiated at the persona→subagent boundary, and it lifts the currently-unused `SubagentStop` primitive (zero subagent-stop matchers in any loam settings.json before this amendment). It EXTENDS the `frame-kernel` component.

**Why structural, not behavioral (the whole thesis).** A drifted doer cannot police itself — the in-context core is a cache hint, not enforcement (integrated-design §1, OS-runtime lens: attention ≠ priority scheduling). The check that keeps the core driving must run in a fresh context the polluted transcript cannot reach (Lerner & Tetlock 1999 unknown-verdict accountability — the fresh-context judge IS that unknown audience; a self-check inside the drift is a co-opted audience). 1a carried the core IN; 1b is the OUT-side guarantee that the core actually governed.

**AC families.** `AC.SSFC.*` (Subagent-Stop Frame-Consistency) — trigger detection (structural-cue gating) + the fresh-context seed (microkernel + objective + result, NEVER the parent conversation) + the isolated-`claude -p` judge path + off-frame surfacing + fail-soft + the outcome-altitude real-finish probe.

**Key decisions baked (recommendations in §3; all autonomous, none owner-gated).** (1) EXTEND `frame-kernel` (the `SubagentStop` hook + a fragment entry) — not a new component. (2) The judge is an isolated `claude -p` via `spawn_isolated_claude` (no API key; spawn-isolation MANDATORY). (3) Trigger on STRUCTURAL cues — consequential subagents (wrote a deliverable / mutated state), read off the transcript — not every subagent. (4) Off-frame action = **non-blocking surface** to the dispatcher for v1 (judge fallibility; integrated-design §6 open-Qs 3+5 unresolved). (5) The judge's seed is microkernel + stated objective + result ONLY — the fresh-context guarantee — explicitly NOT the parent transcript.

**F2 RF on scope realism (full §10).** The natural shape EXTENDS the sealed `frame-kernel` fence (one new hook + one new src module + a fragment entry + tests). The fragment is authored + tested as a portable declaration; live-activation merge + workspace-sync auto-composition stay OUT OF SCOPE exactly as 1a §7 left them (RF-1). Two named risks carried, not silently resolved: the judge-rubric leakage / known-audience-collapse open question (integrated-design §6-Q3, RF-3) and the intent-derivation half of the objective check depending on an objectives surface that does not exist yet (§6-Q4, RF-2).

## §3 Halt-and-surface BEFORE build (named decisions, recorded + recommended)

All decisions below are **autonomous** (method-level, in-scope per the dispatch). Each carries a recommendation; none is owner-gated. Recorded here so the builder does not re-derive.

**FEASIBILITY (resolved at plan-authoring — CONFIRMED; Tier-0).** *Can a `SubagentStop` hook ACCESS the finished subagent's result to judge it?* **YES.** Tier-0 evidence: the official Claude Code hook contract (`~/.claude/plugins/marketplaces/claude-plugins-official/plugins/plugin-dev/skills/hook-development/SKILL.md`) states every hook receives JSON via stdin with the common field **`transcript_path`** (the path to the session/subagent transcript), and §SubagentStop ("Execute when subagent considers stopping … Similar to Stop hook, but for subagents") — so a `SubagentStop` hook reads the FINISHED subagent's transcript (its full output/result) from `transcript_path`. The changelog corroborates the contract is live + evolving for these events (`Stop and SubagentStop hook input now includes background_tasks and session_crons fields`; multiple `prompt-type Stop/SubagentStop` fixes). **The mechanism is feasible — the build does NOT rest on an unavailable primitive.** Residual live-version risk (does the running Claude Code deliver a readable transcript at SubagentStop) is carried as the AC.SSFC.S outcome-altitude probe + §8 halt-trigger #1, exactly as 1a carried its SubagentStart residual.

**D-SSFC.1 — Fence: EXTEND `frame-kernel`.** *Recommendation:* extend the sealed `frame-kernel` component (rationale in §2). Manifest names `frame-kernel` with `frozen_baseline: false` + the existing `extra_allowed_prefixes` (`framework/frame-kernel/`, `kernel/`). No new component.

**D-SSFC.2 — How the judge runs: isolated `claude -p` via `spawn_isolated_claude` (no API key; spawn-isolation MANDATORY).** *Recommendation:* the judge is a `claude -p` call seeded with the microkernel + objective + result, invoked through the SEALED `spawn_isolated_claude(argv, capture_output=True, text=True, timeout=...)` entry-point (`framework/tools/loam-spawn-isolation/`). This is a HARD constraint, not a preference: an un-isolated `claude -p` loads the Telegram plugin and SIGTERM-steals the operator's single bot-poller slot — the PROVEN cause of recurring Telegram drops (`feedback_spawned_claude_must_isolate_telegram_plugin`). `spawn_isolated_claude` resolves THREE constraints in one composition: (a) it injects `--strict-mcp-config` + an empty MCP config (no plugin load → no bot-slot theft); (b) `isolated_env` scrubs `ANTHROPIC_API_KEY` so the spawn uses subscription auth (`feedback_no_anthropic_api_key` — there is NO API key; loam LLM calls go through `claude -p`); (c) it sets `CLAUDE_PERSONA=loam-isolated-spawn` (belt-and-braces — the spawn does not start a competing poller even if it loaded the plugin). The judge therefore does NOT hand-roll a `claude` argv — it calls the mandated entry-point (Lens 1: compose on the sealed isolation surface, reinvent nothing). The brief MUST name this entry-point + the mandate.

**D-SSFC.3 — Trigger / scope: STRUCTURAL-cue (consequential subagents only).** *Recommendation:* gate the judge on a STRUCTURAL cue read off the subagent transcript — fire ONLY when the subagent did something consequential (wrote/edited a deliverable file, mutated state — a Write/Edit/Bash-mutation tool use appears in the transcript), NOT on every subagent. Rationale: judging EVERY subagent is a per-dispatch cost/latency tax that gets disabled (integrated-design §6-Q1 — "too broad = per-turn tax that gets disabled"; all six lenses flagged the trigger as the main empirical knob). Structural cues fire deterministically from the transcript (not a semantic judgment by the possibly-drifted pass — integrated-design §2-J: "trigger on structural cues, not semantic ones"). A trivial read-only / question-answering subagent → no consequential cue → no judge call → near-zero cost. The exact cue set is a build-time-empirical knob (§6-Q1); the plan pins the SHAPE (consequential = wrote-deliverable / mutated-state), the builder tunes the precise cue list. Keep it cheap + bounded: one judge call max per finishing subagent, short timeout, fail-soft.

**D-SSFC.4 — Off-frame action: NON-BLOCKING surface to the dispatcher (v1).** *Recommendation:* on an off-frame verdict, the hook SURFACES the flag to the dispatcher (emits a `systemMessage` / `additionalContext` flag naming the subagent + the frame-inconsistency + the judge's reason) — it does NOT hard-block the subagent's return for v1. Rationale: the judge is fallible (an LLM verdict, n=1); a hard block on a false-positive aborts good work, and the anticipatory benefit of the judge is unverified for LLMs (integrated-design §6-Q5 — "don't claim the anticipatory benefit until measured"). A non-blocking surface delivers the corrective benefit (the dispatcher SEES the off-frame flag + can re-aim) without the false-positive blast radius. Hard-block is a deferred escalation (§7) once the trigger + verdict reliability is measured. "Do NOT silently pass" is honored: off-frame ALWAYS surfaces; what v1 declines is the hard ABORT, not the surface.

**D-SSFC.5 — The unknown-verdict seed: microkernel + objective + result ONLY (fresh context; NOT the parent conversation).** *Recommendation:* the judge's context is assembled FRESH and contains exactly three things — (a) `kernel/loam-microkernel.md` (read verbatim, the same TCB 1a injects; license boilerplate stripped, reusing 1a's render path); (b) the subagent's STATED OBJECTIVE (its dispatch task text, recoverable from the transcript head or the SubagentStop envelope); (c) the subagent's RESULT (its final output, recoverable from the transcript tail). It is seeded via the isolated `claude -p` prompt, NOT by resuming or inheriting the parent session. The parent conversation is explicitly EXCLUDED — that is the load-bearing fresh-context guarantee (integrated-design §1: the check must run in a frame the polluted conversation cannot reach; §2-J: "seeded with only the microkernel + the proposed action — never the polluted transcript"). The judge "COMPARES against the core" (does this result derive from the microkernel + the stated objective?), it does NOT ask the doer "did you consider the core?" (integrated-design §8: the heads-down builder always answers yes).

## §8 Halt triggers (in-flight conditions that abort the build)

1. **Feasibility falsified at build time:** if, when wiring the hook, the `SubagentStop` event does NOT deliver a readable subagent transcript/result (the AC.SSFC.S real-finish probe comes back unable to READ the off-frame result, or `transcript_path` is absent/empty in the running version), HALT — the OUT-side mechanism is infeasible in this Claude Code version; surface with the probe evidence + the alternative (judge seeded from the SubagentStop envelope's own result field if one exists; or move the check to a `PostToolUse`-on-Task-completion shape).
2. **Spawn-isolation cannot be satisfied in the hook context** — if `spawn_isolated_claude` cannot run from inside a `SubagentStop` hook (e.g. the hook env forbids the subprocess, or the isolation assert fails), HALT and surface — do NOT fall back to a bare `claude -p` (that re-opens the PROVEN Telegram-drop kill-vector). The named alternative: a `prompt`-type or `agent`-type hook (the SKILL contract supports both for SubagentStop) that the runtime isolates natively — evaluate it rather than shipping an un-isolated spawn.
3. **Fence breach:** if the natural implementation needs to EDIT a sealed component beyond `frame-kernel` (e.g. modifying `spawn_isolated_claude` itself, or `memory_consumer`, rather than calling it) — HALT; that widens a second sealed fence; surface for a manifest entry rather than silently widening.
4. **No recoverable stated-objective** — if neither the SubagentStop envelope nor the transcript carries the subagent's stated objective, the objective-the-one-requested check is unseedable; HALT and surface, fall back to the microkernel-frame-consistency check only (the named degraded mode), do not invent an objective.

## §10 F2 Ruthless Feedback (honest doubts; named design risks)
