## §1 — Outcome shape (the "why")

**Owner's operative intent (binding-spike report 2026-05-15, surfaced as the owner-domain finding):**

> A non-tech user who runs the documented Quickstart *verbatim* (`git clone → cd loam → python -m venv .venv + pip → loam init <ws> → cd <ws> → claude`) must land in a workspace whose scaffolded SessionStart hooks **run** — so the sealed memory-session-continuity substrate (`loam.primary_persona.cli session-start`) and the orchestrator (`pos_session_start.py`) actually emit their session-start context on the first session — with **NO manual venv-build step inside the workspace and NO hook-fix step**. Today they do not: both hooks exit 127 because the interpreter they name does not exist.

**The single outcome this plan delivers:**

> After the documented Quickstart's `loam init <ws>` (the install-clone venv built per README step 2; NO additional manual step inside `<ws>`), the SessionStart hook commands scaffolded into `<ws>/.claude/settings.json` resolve to an interpreter under which `loam.primary_persona` and the orchestrator `pos_session_start.py` are importable, such that opening `claude` in `<ws>` runs the persona + orchestrator session-start enrichment on turn one (exit 0, context emitted) — not exit 127.

**The failure that triggered this (evidence-grounded, verified from canonical source this turn — not from the spike report's word):**

- `bootstrap_new_workspace` (`new_workspace.py:928`) calls `_scaffold_persona_binding(workspace_root=new_ws_path, handle=persona_handle, loam_root=framework_dir)` where `framework_dir == <ws>/framework/` (the `git clone` target — VERIFIED `new_workspace.py:917-927` in-code comment + `:931` `loam_root=framework_dir`).
- `_scaffold_persona_binding` (`:698-702`) calls `build_persona_session_start_inner_hook(loam_root)` and `build_supervisor_stanza(loam_root, extra_inner_hooks=[…])`, then `merge_session_start(...)` writes the envelope into `<ws>/.claude/settings.json`.
- `build_supervisor_stanza` (`first_run_settings.py:283-285`) constructs `python = loam_root / ".venv" / "bin" / "python"` and `script = loam_root / "framework" / "orchestrator" / "scripts" / "pos_session_start.py"`. `build_persona_session_start_inner_hook` (`session_start_emitter.py:388-389`) constructs `python = loam_root / ".venv" / "bin" / "python"`. With `loam_root == <ws>/framework/`, both hooks invoke `<ws>/framework/.venv/bin/python …`.
- **`bootstrap_new_workspace` NEVER builds `<ws>/framework/.venv`.** VERIFIED: zero `venv.create` / `python -m venv` / `EnvBuilder` / `pip install` / `-m pip` calls anywhere under `framework/workspace-bootstrap/src/` (grep this turn, empty result). The README Quickstart's `python3.13 -m venv .venv` (README:40) builds the venv in the **install clone** (`./loam/.venv`), not in `<ws>/framework/`. The README's own §62-72 note claims the workspace is *"self-contained from that point"* with *"its own copy of the framework under `<workspace>/framework/`"* — that claim is **false for the interpreter the scaffolded hooks depend on**.
- Net (confirmed empirically by the spike report's live `hook_response` capture, exit_code 127, both hooks): persona-IDENTITY binds (the `agent: primary` key + `<ws>/.claude/agents/<handle>.md` — surfaces Claude Code reads directly at session init, independent of the hook), but persona/orchestrator session-start ENRICHMENT is dead on every fresh-init session.

**Prime-objective ladder (per `feedback_value_proposition_as_prime_objective` + plan-docs §4):**

- **AC.PO.1** (translation-burden test, `docs/VALUE_PROPOSITION.md`): the primary persona's session-start enrichment — the memory/active-thread context it reads at SessionStart so it holds context across sessions — is a core part of the translation layer. A fresh-init workspace where that enrichment silently exits 127 delivers a persona that has *identity but no memory continuity on turn one* — a degraded translation layer, the predecessor amendment's claimed AC.PO.1 win only half-realised. Every AC in this plan ladders to AC.PO.1.
- **AC.PO.2** (harness-toolkit test): a seal-test that drives the real scaffolded hook command on a fresh workspace and asserts it runs (AC.LIVI.2) is a reusable structural guarantee — it makes "the scaffolded hooks actually work on a fresh init" a CI-caught invariant, not a thing discovered by a downstream spike. That is harness toolkit, not a one-off fix. AC.LIVI.2/.S ladder to AC.PO.2.

`docs/STATE.md` records the predecessor amendment's "non-tech-user quickstart now lands persona-active" shipped-state line; this plan closes the silent gap behind that line so the claim is true for *enrichment*, not only identity.

**Root-cause synthesis:** `loam init` writes a correct SessionStart envelope whose two hook commands invoke `<ws>/framework/.venv/bin/python`, an interpreter `bootstrap_new_workspace` never creates and the documented Quickstart never builds inside `<ws>/framework/`.
